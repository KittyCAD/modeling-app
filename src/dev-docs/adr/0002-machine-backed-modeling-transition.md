# Reuse modelingMachine while moving Modeling into editor views

Moving the file route's execution and scene ownership into independent editor views is already a substantial architecture change. Use a view-owned instance of `modelingMachine`, its sketch child actors, and the existing toolbar and dialogs for the initial transition. Preserve their interaction flows through explicit document, history, native-runtime, settings, and picking adapters, so colleagues can review ownership changes without also reviewing replacement CAD algorithms.

The editor remains the authority for source text, undo history, and persistence. Each Modeling view owns its connection, native model, manager, and actors. The machine borrows those resources; it does not acquire a global editor, singleton connection, second save owner, or competing scene-input controller. An external edit or execution-setting change retires that owner before executing a replacement model.

Independent tool and interaction contributions remain the intended direction. The earlier Circle/move controllers, contributed command definitions, dialog modes, and sketch-session prototype demonstrated that direction; they are deferred from the initial migration rather than rejected. Introduce them incrementally after the editor ownership transition, with one authoritative interaction implementation at a time. Extract an existing behavior behind explicit dependencies, adapt the legacy machine to it, and exercise both consumers before replacing a machine flow. A contribution must not start a second native editing session alongside the active machine child.

The existing selection and presentation boundaries provide migration seams. A sketch interaction changes the activity within a Modeling editor mode; it does not create another document or editor presentation mode. The initial interaction-session facade projects machine state for view extensions. Later contributions can replace individual flows without requiring an all-at-once removal of XState or making actor internals the public extension API.

This refines the proof-of-concept scope in [ADR 0001](0001-app-owned-scene-host.md): the initial consumer reuses the broader legacy tool system instead of individually porting every tool. Reuse makes those tools reachable but does not establish tested parity for every operation, renderer, or project-dependent feature. Live renderer checks and the remaining project/export and feature-tree adapters remain explicit follow-up work.
